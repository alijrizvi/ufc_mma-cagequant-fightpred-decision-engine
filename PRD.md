# Product Requirements Document (PRD): CageQuant Decision Engine

## 1. Executive Summary
CageQuant is an enterprise-grade Decision Intelligence Engine designed for UFC Lightweight fight trajectory forecasting, quantitative risk analysis, and dynamic tactical stance optimization. It utilizes a 10-second stochastic interval telemetry generator, calibrated XGBoost probability modeling, Monte Carlo risk simulation ($N=1,000$), and a verified FastMCP Agentic Analytics copilot.

## 2. Core Functional Requirements
* **FR-01 (Data & Semantic Layer):** Ingest historical metrics into embedded DuckDB schemas governed by `config/metrics.yml` contracts.
* **FR-02 (Telemetry Discretization):** Generate 10-second interval telemetry using a stochastic interpolation model calibrated against historical round-level strike distributions.
* **FR-03 (Calibrated Predictive Modeling):** Predict dynamic win probabilities per interval using `xgboost.XGBClassifier`, evaluated via Brier Skill Score ($BSS > 0.0$) against empirical base rates.
* **FR-04 (Unsupervised Archetypes):** Cluster fighters into 4 tactical styles using PCA and K-Means, and retrieve historical peer match-ups using KNN Euclidean distance matching.
* **FR-05 (Stochastic Risk Engine):** Run $N=1,000$ Monte Carlo bout iterations with Gaussian damage volatility to calculate expected win rates, method-of-victory distributions, and 95% duration confidence intervals.
* **FR-06 (Tactical Stances):** Model output trade-offs across 4 professional combat states (Standard, High-Output Power, High-Efficiency Flow, Ascended Peak Output).
* **FR-07 (Agentic Analytics Suite):** Expose analytical tools via FastMCP (`src/agent/tools.py`), orchestrate reasoning loops (`copilot.py`), and enforce receipt-style numerical verification (`auditor.py`).
* **FR-08 (Deterministic Evals):** Benchmark agent tool selection and numerical accuracy across 20+ golden scenarios (`evals/`).

## 3. Non-Functional & Governance Requirements
* **NFR-01 (Performance):** Single deterministic simulation trajectory must execute in $<15\text{ ms}$.
* **NFR-02 (Verification):** 100% of numerical claims generated by the agent must pass `AnalyticalAuditor` tolerance checks against ground-truth tool outputs.
* **NFR-03 (CI Determinism):** GitHub Actions CI integration tests must run against mocked LLM outputs to ensure 100% reproducible execution without external API billing.
* **NFR-04 (Attribution & Legal):** Include explicit non-gambling disclaimers and synthetic data attribution terms in `LEGAL.md`.
